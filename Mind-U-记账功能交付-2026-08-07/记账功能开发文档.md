## 2. 产品定位

Mind U 的核心体验是通过自然语言和语音快速记录生活信息。记账功能延续同一产品逻辑：

> 用户说出一笔消费 → 系统识别描述、金额、日期和类别 → 用户确认或修改 → 保存到分类帐本 → 按月、季度、年度汇总。

记账功能不是传统复杂财务软件，而是一个低操作成本、语音优先的个人生活支出记录工具。

第一版重点解决：

- 用户不需要先进入表单逐项填写。
- 用户说一句话即可生成一笔支出草稿。
- 系统自动建议类别，但用户拥有最终决定权。
- 用户可以快速了解一个周期内的钱主要花在什么类别。
- 帐目与现有记录一样优先保存在本机，并进入现有备份和 iCloud 同步结构。

## 5. 记账核心用户流程

### 5.1 正常语音记账流程

1. 用户进入“记账”页面。
2. 用户点击“语音记一笔”。
3. App 启动独立的记账语音识别器。
4. 用户说出消费内容，例如：

   `今天买洗面奶 129 元`

5. App 将语音转换为可修改文字。
6. App 从文字中解析：

   - 描述：买洗面奶
   - 金额：129
   - 日期：今天
   - 类别：美容护理

7. 页面同时显示：

   - 可修改的语音识别文字。
   - 金额、日期和类别理解结果。
   - 简短记账确认卡。

8. 用户可以直接确认，也可以修改草稿。
9. 用户点击“确认记账”。
10. App 保存帐目并显示“已记账”。
11. 新帐目进入最近帐目、全部帐目和周期统计。

### 5.2 金额未识别

如果语音中没有可识别金额：

- 保留语音识别文字。
- 不生成有效的 `ExpenseDraft`。
- 页面提示用户补充类似“129 元”的金额。
- 不允许直接保存一笔金额为 0 的帐目。

### 5.3 用户修改

确认前允许修改：

- 消费描述。
- 金额。
- 日期。
- 类别。

用户修改后的值拥有最高优先级，保存时不再重新覆盖为最初识别结果。

### 5.4 修改类别

用户点击确认卡中的类别后：

1. 打开类别选择页面。
2. 展示全部内置类别和自定义类别。
3. 当前类别显示勾选状态。
4. 用户点击任一类别即可完成修改。
5. 类别列表底部显示“新增自定义类别”。

### 5.5 新增自定义类别

当前版本支持：

- 输入自定义类别名称。
- 从五种柔和颜色中选择类别颜色。
- 自动使用 `tag` 图标。
- 新增成功后自动选中新类别。

当前版本不支持修改已创建类别的名称、图标、排序或删除类别。

## 8. 自动分类优先级

分类器实现位置：

`YijiCore/Sources/YijiCore/Parsing/ExpenseParser.swift`

当前优先级从高到低为：

1. 自定义类别名称直接命中。
2. 育儿。
3. 宠物。
4. 住房。
5. 旅行。
6. 美容护理。
7. 医疗健康。
8. 教育成长。
9. 保险金融。
10. 娱乐社交。
11. 交通。
12. 餐饮。
13. 生活日用。
14. 购物。
15. 待分类。

优先级用于处理一句话同时包含多个类别关键词的情况。

示例：

| 输入 | 识别类别 | 原因 |
|---|---|---|
| 给孩子买衣服 299 元 | 育儿 | 对象优先于商品类别 |
| 买猫粮 120 元 | 宠物 | 宠物对象优先 |
| 搬家公司 680 元 | 住房 | 搬家明确属于住房 |
| 买洗面奶 129 元 | 美容护理 | 当前默认产品规则 |
| 买投资产品 5000 元 | 待分类 | 投资本金不是消费 |
| 投资产品手续费 20 元 | 保险金融 | 手续费属于消费 |

## 9. 金额识别规则

当前支持以下形式：

```text
¥129
￥129
129元
129 元
129块
129块钱
花了129
支付129
买了129
```

支持：

- 整数。
- 最多两位小数。
- 千位分隔符，例如 `1,299.50 元`。

限制：

- 当前不解析中文数字，例如“一百二十九元”。
- 当前不处理一句话中的多个金额。
- 当前默认取第一个符合规则的金额。
- 当前不识别负数、退款或收入。

## 10. 日期识别规则

当前支持：

- 今天／今日。
- 昨天／昨日。
- 前天。
- `8月7日`。
- `8月7号`。
- `2026年8月7日`。

如果没有日期，默认使用当天日期的开始时间。

当前限制：

- 不识别“上周五”“下个月”等复杂相对日期。
- 不识别具体消费时间，只保存日期。
- 无效日期会回退到今天。

## 11. 数据模型

### 11.1 Expense

```swift
public struct Expense: Identifiable, Hashable, Codable, Sendable {
    public let id: UUID
    public var title: String
    public var amount: Double
    public var categoryID: String
    public var spentAt: Date
    public var source: CaptureSource

```

字段说明：

| 字段 | 含义 |
|---|---|
| `id` | 帐目唯一标识 |

| `amount` | 支出金额，当前默认人民币 |
| `categoryID` | 内置或自定义类别 ID |
| `spentAt` | 消费日期 |
| `source` | 记录来源，当前记账保存为 `.voice` |
| `originalTranscript` | 原始语音识别文字 |
| `createdAt` | 创建时间 |
| `updatedAt` | 更新时间 |

`ExpenseDraft` 只存在于确认前，不直接持久化。

## 12. 数据持久化

实现位置：

`YijiApp/Persistence/FileBackedVaultStore.swift`

记账数据与原有记录、提醒和搜索历史保存在同一个 `PersistedVault` 中：

```swift
struct PersistedVault: Codable, Equatable, Sendable {
    var records: [Record]
    var reminders: [Reminder]
    var searchHistory: [String]
    var expenses: [Expense]
    var expenseCategories: [ExpenseCategoryDefinition]
    var modifiedAt: Date?
    var lastWriterDeviceID: String?
}
```

默认本地文件路径：

```text
Application Support/Yiji/vault.json
```

### 12.1 保存帐目

保存流程：

1. 读取当前 `PersistedVault`。
2. 移除相同 ID 的旧帐目。
3. 添加新帐目。
4. 按消费日期和创建时间排序。
5. 更新 `modifiedAt` 和设备 ID。
6. 原子写入本地 JSON。
7. 触发现有 iCloud 同步。

### 12.2 删除帐目

删除时按照 `Expense.id` 移除，并重新写入及同步整个 Vault。

### 12.3 更新类别

新增自定义类别时更新 `expenseCategories`，并与帐目使用同一套持久化和同步流程。

## 14. iCloud 同步

记账功能复用现有：

`CloudKitVaultSyncCoordinator`

同步单位是整个 `PersistedVault`，不是单独的 Expense CloudKit Record。

优点：

- 实现简单。
- 与现有记录和提醒同步方式一致。
- 新字段可通过 Codable 向前兼容。

当前限制：

- 多设备同时修改整个 Vault 时，仍依赖现有修改时间和写入设备逻辑解决冲突。
- 尚未实现帐目级字段合并。
- 大量帐目后整个 JSON 同步体积会持续增加。

如果未来帐目数量达到数万条，建议将 Expense 拆分为独立 CloudKit Record，并支持增量同步。

## 15. 语音识别架构

记账使用独立的：

```swift
let expenseSpeech = SpeechTranscriber()
```

记录页面继续使用：

```swift
let speech = SpeechTranscriber()
```

两者分开是为了防止：

- 记账语音覆盖普通记录草稿。
- 普通记录页面的搜索或提醒识别误触发记账解析。
- 两个页面共享 transcript 后出现状态串线。

`AppModel.bindChildObjects()` 会将两个语音识别器的 `objectWillChange` 转发给 AppModel，确保 SwiftUI 页面及时刷新录音状态。

### 15.1 权限

需要：

- 麦克风权限。
- 语音识别权限。

权限被拒绝时：

- 显示错误状态。
- 提供前往系统设置入口。
- 用户仍可在识别文字输入框中手动输入包含金额的内容。

## 16. 周期统计

### 16.1 月度

筛选与当前日期处于同一年和同一月的帐目。

### 16.2 季度

季度计算公式：

```swift
(month - 1) / 3
```

筛选当前年份、当前季度的帐目。

### 16.3 年度

筛选与当前日期处于同一年的帐目。

### 16.4 类别汇总

1. 按 `categoryID` 分组。
2. 计算每组金额合计。
3. 计算类别金额占周期总金额的比例。
4. 按金额从高到低排序。
5. 圆环图展示全部类别。
6. 右侧图例最多展示金额最高的 5 个类别。

### 16.5 圆环图

当前使用自定义 SwiftUI `Shape` 绘制连续扇区，并用中心圆遮罩形成圆环。

未使用 `SectorMark`，原因是工程最低支持 iOS 16，而 `SectorMark` 需要更高系统版本。

当前配色：

- 开心果绿：`#B7C79F`
- 柔珊瑚粉：`#F29A92`
- 粉雾蓝：`#B8DDEA`
- 浅薰衣草紫：`#D9C9E8`
- 奶油黄：`#F3D8A6`

其他类别使用同一年轻、低饱和色系扩展。

## 19. 验收标准

### 19.1 语音与草稿

- 用户可以启动和停止记账语音识别。
- 识别文字可以修改。
- 识别到金额后生成确认卡。
- 没有金额时不保存无效帐目。
- 记录页面与记账页面的语音草稿不会互相覆盖。

### 19.2 分类

- 默认类别名称与产品定义一致。
- 搬家识别为住房。
- 洗面奶默认识别为美容护理。
- 育儿和宠物遵循对象优先。
- 投资本金不直接计入消费类别。
- 用户可以覆盖系统建议类别。
- 用户可以新增自定义类别。

### 19.3 保存与统计

- 确认后帐目持久化。
- 重启 App 后帐目仍存在。
- 最近帐目顺序正确。
- 月度、季度、年度金额正确。
- 类别金额与百分比之和与周期总额一致。
- 删除帐目后统计立即更新。

### 19.4 数据兼容

- 旧备份可正常导入。
- 新备份包含帐目和类别。
- iCloud 不可用时仍可本地保存。
- iCloud 恢复后可以继续使用现有同步流程。

## 20. 隐私与合规

记账内容可能包含敏感个人消费信息。

产品和开发应遵循：

- 语音仅用于用户主动触发的识别。
- 帐目优先保存在用户设备本地。
- 不在日志中输出完整消费描述、金额或原始语音文字。
- 备份由用户主动生成或导入。
- iCloud 同步状态需要对用户透明。
- 后续接入第三方分析工具时，不上传帐目明细。
- 后续接入银行、支付平台或 OCR 时，需要更新隐私政策和 App Store 隐私标签。

## 22. 已知问题与技术债务

1. 金额使用 `Double`，长期财务计算更适合使用十进制定点值或以“分”为单位的整数。
2. 当前默认币种写死为 CNY，模型没有 `currencyCode` 字段。
3. 自定义类别管理能力不完整。
4. 已保存帐目只能删除，不能编辑。
5. 统计只能查看当前周期，不能选择历史月份或年份。
6. 圆环图图例最多显示前五个类别，其他类别仍在图中但没有单独图例。
7. 语音解析基于关键词和正则表达式，不支持复杂自然语言、多金额或中文数字。
8. 用户修改类别后，系统尚未学习个人偏好。
9. 整个 Vault 作为一个 JSON 同步，帐目很多时同步效率会下降。
10. 当前没有专门的记账 UI 自动化测试。

## 26. 总结

Mind U 记账第一版已经建立完整的基础闭环：

> 独立语音录入 → 结构化解析 → 用户修改与确认 → 本地保存与同步 → 分类帐本 → 周期汇总。

当前实现适合作为语音支出记账 MVP。下一步最有价值的工作不是立即增加复杂资产功能，而是先完成真机语音验证、已保存帐目编辑、历史周期选择、自定义类别管理和分类偏好学习。
